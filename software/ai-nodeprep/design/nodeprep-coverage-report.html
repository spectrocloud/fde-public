What the fresh-node run actually covered

Every step the controller performed on a freshly reprovisioned worker node, mapped line-by-line against the 979-line bash script it replaces — with the live evidence for each, and an honest list of what is still gated or unconverted.

Two full bare-metal reprovisions: bm-a-rtx6k-7 on agent/controller 0.1.10 (machine …b6ppf-vt85f) and bm-a-rtx6k-6 on 0.1.11 (machine …b6ppf-tjc9j) · no-Mellanox workers · profile gpu-worker-v105 · reprovision via Node deletion

§1How this was verified

The Node object for the worker was deleted, causing CAPI to deprovision and MAAS to reprovision the machine from scratch (~25 min). The fresh node joined with the node.spectrocloud.com/ai-worker: "true" label, the controller adopted it, and the agent ran the full phase machine against bare metal — the same starting point the bash script has on a fresh rack unit. Because the box carries no Mellanox NICs, every hardware-mutating step exercised its detection-and-skip gate; the gates are live-verified, the mutation bodies are declared below as v0.2. Two controlled reboots then proved the boot path. After the full companion-package set and firmware-cache reuse landed (0.1.11), the whole reprovision was repeated end-to-end on a second bare-metal re-rack — the final §2 entry.

§4What v0.1 adds beyond the bash script

The rewrite was an opportunity to fix what the script could not do, and every item below was exercised in this run.

  • CAPI pause/unpause of the Machine — the node is owned exclusively during prep (MachinePaused/MachineUnpaused events, annotation verified on the Machine, released on Ready and on de-adoption). The bash script had no notion of CAPI at all.
  • sha256-verified downloads with .tmp+rename — a truncated or MITM'd BFB cannot be flashed.
  • Firmware cache reuse — a local spcx copy that still hashes to the profile's checksum is reused instead of re-fetched, so re-preps move zero bytes over the wire (proven live: 1.5 GB reused); without a configured checksum nothing is trusted and the fetch always runs.
  • Declared, inspectable state — the 15-step ledger, phase, reboot count and per-step messages are a kubectl object, not a file inside a container image.
  • Crash-safe resume — a Failed NodePrep recovers by annotation without re-imaging (used live after the aptPackages bug).
  • Per-step criticality — a failed critical step (SR-IOV, udev, lossless RoCE, OVS, ACS) blocks Ready and holds the taint; non-critical failures do not poison the node.
  • Boot verification protocol — boot-ID change detection, reboot counting, taint held until the new boot is verified, all evented.
  • Host-mutation guardrails — detect-only mode (no -host-mutations) turns every mutating step into a Blocked report instead of an error.
  • OOM-safe heavy exec — apt/dpkg run in transient host systemd units, not as pod children; the agent pod cannot be OOM-killed by host package management (the 0.1.7 fix, shipped before this run).
  • Render-time syntax gate — the boot hook is parsed by the host's own /bin/sh before it can replace a working file (the 0.1.10 fix from reboot #1).
  • Auditability — every host command, download and transition is logged with duration and bounded output, and surfaced as Kubernetes events.

§5Honest gaps — what is not converted yet

Ordered roughly by when they would bite. The first block only matters once a Mellanox-equipped system is provided; the second block applies to every node.

On the Mellanox path (waiting on hardware)

  • Flash/config mutation bodies — bfb-install, mlxconfig, sriov_numvfs writes, VF GUID synthesis, udev rule generation, mlnx_qos/mlxreg, OVS bridge convergence, ACS setpci, NFSoRDMA modules: gates are in and verified, bodies land in v0.2 with full Detect/Apply/Verify semantics. Their package prerequisite is met: mft (and the other bash companion packages) are in the profile and verified installed on the test nodes, so the gated steps will find their tools when the hardware arrives.
  • Post-software-stage reboot trigger — the reboot protocol exists and is proven, but requestReboot is not yet called by any step; the bash script's "reboot to inithw" after the software stage needs that one-line trigger wired into the Mellanox path.
  • netplan gpu_fabric_eth generation — fn_config_stage's file writing has no equivalent.
  • SR-IOV device-plugin pod bounce after VF creation, so the plugin re-discovers VFs.
  • rshim restart before flashing.

On every node

  • grub assembly (90-nodeprep.cfg) — grubParams detects missing cmdline parameters and Blocks by design; writing them is the v0.2 boot path. The profile configures none today, so the step skips.
  • apt upgrade, linux-headers hold, gcc-12, apt autoremove — not implemented. The profile field aptUpgrade exists but no step consumes it yet (this profile sets it false, so behavior matches today).
  • LLDPD configuration — the lldpd package installs (verified in reprovision #2), but the bash script's LLDPD config-file block has no equivalent yet.

§6Defects the live loop caught (and the fixes shipped)

Each of these passed the unit-test suite and failed only on real hardware — the reason the live-cluster mandate paid for itself.

Agent pod OOMKilled during DOCA install (0.1.7, first live pass). apt-get install doca-all as a pod child counted its memory against the pod limit. Fix: heavyHostExec runs package management in transient host systemd units via systemd-run — host-accounted memory, fail-fast on concurrent retries, idempotent re-runs. Live-proven across this run's installs.

Missing install subcommand (0.1.8, this run's fresh node). apt-get --yes doca-all → "E: Invalid operation doca-all", exit 100, 5 attempts exhausted, NodePrep Failed. Its gate tests asserted decisions, not command shape. Fix in 0.1.9; the run then completed to Ready in ~1 minute via the resume path.

Stray quote in the rendered boot hook (0.1.9, reboot #1). One bad character made dash reject the whole script at boot; the kubelet manager-state reset silently never ran and the node crashlooped — the exact failure class the hook exists to prevent. Fix in 0.1.10: candidate script is validated by the host's own /bin/sh (sh -n via nsenter) before it can replace a working file, plus a test parsing all 21 rendering variants with real sh -n. Reboot #2 then proved the repaired hook end-to-end with planted corruption.

Test-harness hygiene: MachineHealthCheck maxUnhealthy was patched to 0% before the reboot tests so its 10-minute Ready-timeout could not deprovision the Machine mid-test, and was restored to 100% after verification completed. The first (unpatched) reboot attempt did get remediated — the cluster deleted the Machine and MAAS re-racked it, which is itself what provided the fresh-node test bed.
